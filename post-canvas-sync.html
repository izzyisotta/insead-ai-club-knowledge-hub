How my Canvas sync works (the Playwright route)

II Isabella Isotta · 20 April 2026 · 5 min read
#canvas #playwright #launchd #auth

Every morning at 7:30am a launchd job logs into Canvas, walks every course, and pulls anything new into my Sources/L##/ folders. New lecture files become uploads. New assignments become to-do items with deadline tracking. I look at one place — Obsidian — and the whole picture is there.

The interesting bit isn't the scrape. It's the auth resilience. INSEAD's ADFS login changes selectors more often than I'd like, so a brittle script breaks weekly. The script I run hasn't broken in six.

The script

The whole thing is one Python file: canvas-sync-playwright.py. It uses Playwright with a persistent browser profile so cookies survive between runs.

~/scripts/canvas-sync-playwright.py
~/.config/canvas-sync/.env       # username + password fallback
~/Library/LaunchAgents/canvas-sync.plist

Auth, in three layers

  1. Cookie reuse. Persistent context. If the session is still alive, just navigate to a course page and we're in.
  2. Silent SSO refresh. If cookies expired (every 1-3 days), navigate to the SSO redirect URL. Most days the IDP refreshes silently and you're back in.
  3. Username/password fallback. If silent refresh fails, fill in the login form using a chain of selectors (in order: id, name, placeholder, ARIA attributes, label-based). Whatever the ADFS UI is wearing today, one of those usually still works.

Then the walk

for course in canvas.list_courses():
    for module in course.modules:
        for item in module.new_items_since(last_run):
            download_to(f"Sources/{course.code}/L{item.lecture_no:02d}/")
            if item.is_assignment:
                add_to_todo_inbox(item)

That's most of it. There's some categorisation — slides go to one folder, readings to another, Harvard/McKinsey blocks get logged for end-of-term batch download — but the core loop is that.

Things that surprised me

  • Throttling matters. Hit Canvas too hard and you get soft-blocked. I throttle to one request every 1.5s and stagger across courses. No failures in three weeks.
  • The session keepalive idea was wrong. I built a daemon that hit the API every hour to "keep the session alive." It didn't. Reading from the API doesn't extend the session. Archived.
  • The auto-tagger is the real win. Once everything was flowing into folders, I added a small Claude step that tags each item by topic. Now I can filter readings by "negotiation" or "case method" instead of by which week it dropped.

What I'd do differently

I started with complicated browser automation. Half of it I could have done with the Canvas REST API — Canvas does have one, even though it's gated. Lesson: check the API surface first, automate the browser only for the parts the API doesn't cover.

Script is in my dotfiles repo. The Claude Code skill that orchestrates it is shared via the attachment. If you're building your own, happy to walk through it — drop a comment.
