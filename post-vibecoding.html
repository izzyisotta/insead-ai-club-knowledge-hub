My vibecoding workflow: prompt to live website without opening a code editor

II Isabella Isotta · 12 April 2026 · 4 min read
#vibecoding #vercel #github-pages #claude-code

I describe what I want built in plain English. Claude Code writes the code, pushes it to GitHub, and it goes live as a website. I never touch code or open a code editor.

Sounds too simple. Is genuinely simple. Five tools doing one thing each.

The five tools

  1. Git — version control. "Save on steroids."
  2. Homebrew — installs developer tools on Mac.
  3. GitHub CLI — gh repo create my-app --public --source=. --push and the repo exists. Two seconds.
  4. Claude Code — writes everything.
  5. Vercel for dynamic sites, GitHub Pages for static.

The flow

  1. Describe what I want in plain English. Sometimes one paragraph, sometimes a page.
  2. Claude Code generates the project. Asks me a few clarifying questions.
  3. I review by clicking around the dev server. Tell Claude what's off.
  4. It iterates.
  5. When it's good: gh repo create + push + deploy. Live URL in under a minute for static, five for dynamic.

What I've built so far

  • insead-excuse-generator — a joke tool that produces plausible reasons for missing INSEAD events. Most-used tool in my section.
  • trove — social media for books, films, and TV. Real app, dynamic, friend matching, AI recommendations.
  • insead-claude-code-demo — the mockup you're looking at right now.

What surprised me

The first deploy is the hard part. Once GitHub Pages or Vercel is hooked up, every subsequent change is just git push. I burned hours on env variables the first time. Five minutes now.

The other surprise: when Claude gets stuck in a loop, start a new conversation. Long sessions accumulate confusion. New chats are free, and they often resolve in 10 seconds what the old chat had been thrashing on for 20 minutes.

Where it doesn't work

Anything that needs real testing matters. I haven't written tests for any of the things above. For trove, that started to bite when I added auth. For tools that nobody depends on, it's fine. For anything you'd put a customer in front of, you need an actual engineer.
